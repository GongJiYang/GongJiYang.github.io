## Chapter 3: Io

参考:

- https://thinktwice.tech/posts/c78e5a81add32ae395311b8e1a40ae4a/

| 角度                                               | Io 的回答                                                    |
| -------------------------------------------------- | ------------------------------------------------------------ |
| **① 核心计算模型**程序到底在做什么？               | **对象之间发送消息，并通过消息的执行产生计算。一切皆为对象,“对象收到消息 → 查找对应的槽（slot）→ 执行”。 |
| **② 基本抽象**这个语言认为最重要的东西是什么？     | **对象（Object）和消息（Message）。** Io 没有传统意义上的 class hierarchy。一个对象可以从另一个对象克隆出来，形成新的对象。拿现有对象作为原型，然后创建新的对象**。 |
| **③ 状态观**世界是变化的，还是不可变的？           | **世界可以变化，而且状态直接存在于对象的槽中。** 对象可以拥有数据，也可以拥有行为；修改对象的槽，就相当于改变对象的状态。Io 因此不是纯函数式语言，而是明显接受**可变状态**。不过由于对象本身就是计算单位，状态和行为天然结合在一起。 |
| **④ 控制观**计算的流程应该如何表达？               | **通过消息发送来表达控制。** “执行某件事”可以理解为“向某个对象发送一个消息”。更有意思的是，Io 的消息本身也是可以被操作的对象，因此程序的结构并不是完全隐藏在编译器里的。再加上异步消息、Future 等机制，Io 可以把**顺序计算和并发计算**用相对统一的消息模型表达。 |
| **⑤ 数据观**数据是什么？数据和代码是什么关系？     | **数据和行为都可以成为对象的一部分。** Io 中对象的 slot 不只是存数据，也可以保存方法。因此一个对象可以同时包含“状态”和“行为”。此外，Io 的消息本身可以被检查和操作，这使得**代码与数据之间的界限比传统语言更模糊**。 |
| **⑥ 抽象机制**语言允许你创造什么新的抽象？         | **通过对象、原型、槽、消息和方法组合新的抽象。** 尤其重要的是：Io 不要求所有抽象都必须先进入一个固定的 class/type 体系。你可以直接创建对象、修改对象、复制对象，并通过消息系统构造自己的领域模型。这也让 Io 很适合构造**内部 DSL**。 |
| **⑦ 组合方式**复杂程序是怎么从简单东西组合出来的？ | **通过对象之间的组合 + 消息发送 + 原型委托。** 一个对象可以拥有其他对象，也可以把消息委托给自己的原型。复杂系统于是可以看成一组相互连接的对象，而不是传统意义上的“类 → 实例 → 方法调用”层级。 |
| **⑧ 错误观**错误、不确定性、异常应该如何处理？     | Io 有异常机制，但从语言哲学上看，它更重要的一点是：**失败也是计算过程中的一种结果，需要由程序决定如何处理。** Io 没有试图用复杂的静态类型系统在运行前消灭大量错误，而是采用动态语言的路线，把很多检查推迟到运行时。 |
| **⑨ 并发观**多个计算同时发生时，语言怎么看待它？   | **通过异步消息和 Future 把并发纳入消息模型。** 普通消息可以理解成“现在发送、等待结果”，异步消息则可以理解成“发送后继续做自己的事情”。Future 就是**“未来会出现的结果”**。所以 Io 的并发思维并不是首先考虑锁和共享内存，而是考虑**对象之间如何异步通信**。 |
| **⑩ 元编程观**程序能不能改变/生成/理解程序本身？   | **非常强。** 这是 Io 很有特色的一面。因为消息、对象、槽、方法等都可以被程序操作，所以程序可以在运行时检查、修改和构造自己的结构。Io 因此具有很强的**反射、元编程和语言扩展能力**。这也是它非常适合研究“语言本身”的原因。 |

Io 可以说是一种不依赖类的、基于原型的小型动态语言。所有的数据都是以对象的形式存储的，赋值和控制流操作也很简单，就像发送普通消息一样。

自 2026 年 4 月以后，既定的实现方式将是使用 WebAssembly（WASI）。相同的二进制代码可以在 wasmtime、Node.js 以及浏览器环境中运行。

Io 的源代码通常是以 `.io` 为扩展名的格式编写的。编译器会生成以 C 语言编写的虚拟机，该虚拟机负责解析消息树。目前的默认构建方式是将这种虚拟机转换为 WebAssembly 格式。

在 WASM 中，并没有像 npm 或 Cargo 这样的中央包管理工具。标准库被包含在发行版中，而主机端的功能则通过 JavaScript 的相互调用来实现。 `DynLib` 、 `AddonLoader` 以及 Eerie 提供的原生插件在 WASM 中是无法使用的。

相应地，核心中的组件是 Importer。每当遇到同名文件时，它会自动在第一次被引用时加载该文件。默认的搜索路径是当前目录，可以使用 `addSearchPath()` 来添加额外的路径。

在 Io 语言中，当你向一个对象发送一个消息（调用一个方法），如果该对象及其原型链中都没有定义这个方法，Io 解释器不会立即抛出错误，而是会去寻找一个名为 `forward` 的特殊方法。

如果你熟悉其他编程语言，`forward` 的功能等同于：
*   **Ruby** 中的 `method_missing`
*   **Smalltalk** 中的 `doesNotUnderstand:`
*   **Python** 中的 `__getattr__` 或 `__getattribute__`
*   **JavaScript (ES6+)** 中的 `Proxy` 对象的 `get` 陷阱

**举个例子：**
假设你想用 Io 写 HTML。你可能想直接写 `html(body(h1("Hello")))`。

*   通常情况下，如果你的代码里没定义 `html`、`body` 或 `h1` 这些方法，程序会崩溃。
*   但是，如果你定义了 `forward` 方法，你可以让它拦截这些“不存在的方法名”。
*   当调用 `html(...)` 时，`forward` 被触发，它拿到“html”这个名字，然后自动生成一个 `<html ...>` 标签。

它允许对象将处理请求的责任**转发**给另一个地方（比如另一个对象，或者一个通用的处理逻辑），而不是直接报错。

`forward` 是 Io 语言的一种**“兜底”机制**。它允许程序动态地响应那些在编写代码时还不存在的方法调用，是实现动态代理、装饰器模式和灵活 DSL 的核心工具。

向任何对象发送异步消息，就能使其成为一个参与者。

### Io 的 Future 到底是什么？

“未来某个时间会得到结果的占位符。”

“事情先同时做起来，真正需要结果的时候再等。”

Future 最有意思的地方：它本身可以被传来传去,所以: “程序不一定要围绕“现在有没有结果”来组织，而可以围绕“结果将来会出现”来组织。”

这就是 Future 的核心思想。

Furture 和 线程 不是一回事,Future 主要描述的是“结果”，而不是“执行者”。

异步发送消息，可以得到一个 Future。把“启动计算”和“得到结果”这两件事情分开。

**自动死锁检测 (Automatic deadlock detection)**。

Future一种“表示尚未完成计算结果”的抽象。

## Chapter 4: Prolog

参考:

- https://www.youtube.com/watch?v=4qJVzOl4wWk

| 角度             | 回答                                                         |
| ---------------- | ------------------------------------------------------------ |
| 本体论           | **世界是一堆**事实（facts）和规则（rules）构成的逻辑陈述集合**——也就是一个"知识库"。程序员不描述"怎么做"，而是描述"什么是真的"。** |
| 计算模型         | **基于合一（unification）的逻辑推理 / 定理证明**。执行 = 给定一个目标（goal），系统尝试通过归结（resolution）证明它能否从已知事实和规则推导出来。 |
| 基本元素         | 基本元素是**项（term）**：原子、数字、变量、复合项（如 `father(tom, bob)`）。所有项地位平等，都可以被合一、传递、构造，没有"数据"和"代码"分离的特殊地位差异——事实、规则、查询本质上都是项/子句。 |
| 状态与时间       | 纯 Prolog 在语义上**不承认状态随时间变化**——变量一旦绑定不可再改（只能靠回溯撤销）。但实践中通过 `assert`/`retract` 可以修改知识库，这是对纯逻辑语义的"逃逸口"，顺序由程序执行的时间顺序（副作用发生的先后）隐式决定，这也是 Prolog 被诟病"不纯"的地方。 |
| 控制结构         | 名义上是**声明式的**（你只写"什么为真"），但实际执行顺序高度依赖**子句顺序 + 深度优先搜索 + 回溯**这一固定策略，程序员必须理解并常常依赖这个隐藏的执行顺序（如利用剪枝符 `!` 控制回溯），所以 Prolog 是"声明式外表下有命令式内核"的典型例子 |
| 数据与代码的关系 | 完全同一。**规则、事实、查询全部都是项（term）**，可以像数据一样被构造、被检查、被断言进知识库（`assert`）。这是 Prolog 与 Lisp 共享的"同像性"（homoiconicity）特点。 |
| 抽象手段         | 主要靠**谓词定义（predicate definition）**——把一组子句打包成一个可复用、可递归调用的关系；此外可以用**高阶谓词**（如 `call/N`、`findall`、`maplist`）把"谓词"本身当作参数传递，实现更高层的抽象。 |
| 组合手段         | 通过**合取（`,`）、析取（`;`）和子句的多重定义**组合目标；合一提供了结构上的组合（项嵌套项）。组合性总体上是好的——子句之间是独立可加的（除了执行顺序副作用和剪枝符会破坏这种纯粹的组合性）。 |
| 错误与不确定性   | **"失败"（fail）是完全正常的控制流**，是逻辑推理的一等结果（"证明不成立"），会自动触发回溯尝试别的分支，而不是像异常那样中断程序。真正的运行时错误则通过独立的 `catch/throw` 机制处理，与"逻辑失败"是两套不同的东西。 |
| 并发模型         | **多个计算单元之间如何通信与同步：共享状态、消息传递，还是数据流？** |
| 反身性 / 元编程  | 程序是否可以将自身表示为数据并对其操作？这种能力是运行时的，还是语言自身也支持扩展？ |
| 认知目标         | 这门语言最终想让程序员用什么"心智模型"去思考问题？           |

Prolog 是一种声明性语言。你只需提供一些事实和推理信息，然后让 Prolog 来完成推理工作。这就像去找一位出色的面包师——你描述出自己喜欢的蛋糕的特点，然后让面包师根据你提供的规则来挑选材料并为你制作出满意的蛋糕。使用 Prolog，你无需了解其中的原理，因为计算机会负责完成所有的推理工作。

Prolog 是一种逻辑编程语言，由 Alain Colmerauer 和 Philippe Roussel 在 1972 年开发。你可以利用这种基于规则的编程语言来表达逻辑和提出问题。与 SQL 类似，Prolog 也适用于数据库操作，但其中的数据是由逻辑规则和关系构成的。和 SQL 一样，Prolog 也有两个部分：一部分用于表示数据，另一部分用于查询数据。在 Prolog 中，数据以逻辑规则的形式存在。这些就是构建程序的基本单元。
