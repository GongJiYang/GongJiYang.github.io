开放申请表:

- 资源内网IP:云主机在内部网络中的地址

- 对外端口号:公网允许访问的端口 (正式环境优先申请 443)
- 协议:TCP或UDP(Web、HTTPS、设备 HTTP 回调均为)
- 端口提供的具体服务

### 操作系统和内存

```powershell
Write-Host "`n=== 1. 操作系统 ==="
Get-ComputerInfo |
  Select-Object WindowsProductName, WindowsVersion, OsBuildNumber,
                OsArchitecture, CsManufacturer, CsModel,
                CsProcessors, CsTotalPhysicalMemory
```

把字节形式的内存换算成 GB，并显示更紧凑的摘要：

```powershell
$cs = Get-CimInstance Win32_ComputerSystem
[PSCustomObject]@{
    Manufacturer = $cs.Manufacturer
    Model        = $cs.Model
    CPU          = (Get-CimInstance Win32_Processor).Name -join "; "
    Cores        = (Get-CimInstance Win32_Processor | Measure-Object NumberOfCores -Sum).Sum
    LogicalCPU   = $cs.NumberOfLogicalProcessors
    MemoryGB     = [math]::Round($cs.TotalPhysicalMemory / 1GB, 2)
    OS           = (Get-CimInstance Win32_OperatingSystem).Caption
    OSVersion    = (Get-CimInstance Win32_OperatingSystem).Version
    Architecture = (Get-CimInstance Win32_OperatingSystem).OSArchitecture
}
```

### CPU 和虚拟化

```powershell
Write-Host "`n=== 2. CPU 与虚拟化 ==="
Get-CimInstance Win32_Processor |
  Select-Object Name, AddressWidth, NumberOfCores,
                NumberOfLogicalProcessors,
                VirtualizationFirmwareEnabled,
                SecondLevelAddressTranslationExtensions
```

重点字段：

- `AddressWidth = 64`：64位系统；
- `VirtualizationFirmwareEnabled`：当前系统是否能看到固件虚拟化能力；
- `SecondLevelAddressTranslationExtensions`：是否能看到 SLAT；
- 云虚拟机中两项为 `False`，通常表示云平台没有向该虚拟机开放嵌套虚拟化。

### 磁盘容量

```powershell
Write-Host "`n=== 3. 磁盘 ==="
Get-Volume |
  Where-Object DriveLetter |
  Select-Object DriveLetter, FileSystemLabel, FileSystem,
                @{N='FreeGB';E={[math]::Round($_.SizeRemaining/1GB,2)}},
                @{N='TotalGB';E={[math]::Round($_.Size/1GB,2)}}
```

检查时不能只看总容量，还要区分：

- 系统盘：放Windows、日志和少量程序；
- 数据盘：放数据库、附件、备份和容器持久化数据；
- 空光驱或未就绪盘：可能显示 `0GB`，不应当作为数据盘使用。

### IP、DNS和网关

```powershell
Write-Host "`n=== 4. IP、DNS、网关 ==="
Get-NetIPConfiguration |
  Select-Object InterfaceAlias,
                @{N='IPv4';E={$_.IPv4Address.IPAddress -join ','}},
                @{N='Gateway';E={$_.IPv4DefaultGateway.NextHop -join ','}},
                @{N='DNS';E={$_.DNSServer.ServerAddresses -join ','}}
```

这里用于识别：

- 服务器内网 IP；
- 默认网关；
- DNS服务器；
- 是否存在多块网卡或多个地址。

云主机看到的地址通常是内网地址。浏览器使用的公网地址可能由云平台的 NAT、负载均衡或WAF映射过来，不能把内网IP直接当作公网IP。

### 关键端口和占用进程

```powershell
Write-Host "`n=== 7. 当前监听端口 ==="
Get-NetTCPConnection -State Listen |
  Where-Object LocalPort -in 80,443,3306,5432,6379,8040,6110,6107,11080,28080,8080,8443 |
  Sort-Object LocalPort |
  Select-Object LocalAddress, LocalPort, OwningProcess,
                @{N='Process';E={(Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue).ProcessName}}
```

本项目相关端口的常见用途：

|  端口 | 常见用途                   | 是否建议公网开放                 |
| ----: | -------------------------- | -------------------------------- |
|    80 | HTTP统一入口               | 可以，由Nginx、IIS或负载均衡监听 |
|   443 | HTTPS统一入口              | 可以，生产环境推荐               |
|  3306 | MySQL                      | 不建议                           |
|  5432 | PostgreSQL                 | 不建议                           |
|  6379 | Redis                      | 绝对不建议                       |
|  8040 | Java后端                   | 通常仅内网或容器网络             |
|  6110 | kqco服务                   | 通常仅内网或容器网络             |
|  6107 | co-service TCP             | 仅需要的内网调用方               |
| 11080 | co-service HTTP            | 通常由统一入口反向代理           |
| 28080 | 管理工具                   | 不建议公网开放                   |
|  8080 | 当前Docker Nginx HTTP映射  | 调试或作为上游入口               |
|  8443 | 当前Docker Nginx HTTPS映射 | 调试或作为上游入口               |

进程显示为 `System` 且PID为4时，通常表示端口由Windows内核HTTP栈代管。结合IIS绑定可以判断是不是IIS占用。

### Windows虚拟化功能

```powershell
Write-Host "`n=== 9. Windows 功能 ==="
Get-WindowsOptionalFeature -Online |
  Where-Object FeatureName -match 'Hyper-V|VirtualMachinePlatform|Microsoft-Windows-Subsystem-Linux|Containers' |
  Select-Object FeatureName, State
```

这一步查看Windows功能是否存在并启用。但需要注意：即使功能可以安装，云平台没有开放嵌套虚拟化时，内部Linux虚拟机依然可能无法启动。

---

筛查下来发现一个严重的问题: 虚拟化能力

```text
VirtualizationFirmwareEnabled = False
SecondLevelAddressTranslationExtensions = False
```

这表示当前Windows虚拟机看不到运行嵌套虚拟化所需的能力。即使底层物理服务器支持虚拟化，也不代表该能力已经透传给当前云虚拟机。

这会直接影响：

- WSL2；
- Hyper-V虚拟机；
- 依赖Linux虚拟机的Docker Desktop后端；
- 在Windows虚拟机内部再启动Linux虚拟机。
