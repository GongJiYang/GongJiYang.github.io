# Old

记外包项目的开发记录.

信息中心给分了一台内网云主机 ,目前只能通过 VPN进入内网管理,若要让公网用户或设备厂商访问,需要另行申请“公网 IP + 防火墙/NAT 端口开放”。

开放申请表:

- 资源内网IP:云主机在内部网络中的地址
- 对应公网IP:信息中心分配或映射的公网地址(由信息中心填写/分配)
- 对外端口号:公网允许访问的端口 (正式环境优先申请 443)
- 协议:TCP或UDP(Web、HTTPS、设备 HTTP 回调均为)
- 端口提供的具体服务

所以现在有云主机和远程访问凭据

- QA:开发文档里有提到对访问电脑的配置要求,所以我是否能用本机电脑访问?

以及我有Windows 管理员账号?

所以我现在的网络关系大致是:使用提供的运维电脑进入信息中心内网的win云主机.

这里还有提供一个win的二级密码,暂时不知道作用,可能是远程桌面或者堡垒机的密码.

正常进行对公网开放我决定通过Nginx的433端口统一承接:

- 浏览器访问
- java后端api
- sso登陆
- 前端静态资源
- 各厂商HTTP/HTTPS回调

80端口,HTTP访问重定向至443的HTTPS

根据部分IOT文档可以了解到,某品牌4G 呼叫器使用 TCP 8800，这是唯一可能需要单独申请公网端口的非 HTTP 服务。

但考虑现在真正进行测试过的IOT品牌只有一个所以暂时不考虑.

最终确认事项:

- 最终生产服务器还是临时测试资源
- “对应公网 IP”是新分配，还是已有固定公网 IP
- 公网 IP 是一对一 NAT，还是负载均衡/WAF 地址
  - 设备厂商会主动把告警发送到平台,WAF 可能把正常设备请求误认为攻击并拦截.
- 能否配置公网 443 → 内网 443，或 443 → 8443。
-  是否要求提供域名和 SSL 证书。
- 是否支持按来源 IP 配置厂商白名单
- VPN 后如何连接服务器
- 服务器能否出网访问
- 公网回调是否经过某云 WAF；若经过，需确认 WAF 是否允许 JSON POST、回调路径及请求体大小。

公网 443 → 内网服务器 443，Nginx 自己配置证书并监听 443。

## BUG

地图无法显示BUG:

- queryYztzl 在查询智能设备数据时，调用的外部设备接口提前关闭了 HTTP 连接

原因:物理设备不在线不是问题；后端把离线/外部不可用错误地升级成 500 才是问题。
所以当前有两条独立失败链:

1. queryYztzl 失败
GssZhtzController.queryYztzl()
→ RecordServiceImpl.queryZnsb()
→ ItoServerImpl.deviceInfo()
→ 外部设备平台
→ Unexpected end of file
→ HTTP 500
queryZnsb() 对每个登记设备同步调用外部平台。任意一个设备请求失败，就终止整个统计接口。
合理行为应该是：
{
  "online": 0,
  "total": 1,
  "sbWaring": 0
}
或者附带：
{
  "status": "DEGRADED",
  "unknown": 1
}
而不是返回 500。
2. querysbListFn 阻断地图
前端初始加载顺序是：
queryYztzl()
→ /iot/jcxx/list
→ /kyfw/sb/queryList?lx=24
→ 组装 mapData
其中 /kyfw/sb/queryList 也因外部设备定位服务 SSL 握手失败返回 500。前端没有局部 try/catch，所以这一步失败后：
mapData 不再赋值
→ 地图 marker 整体不渲染
→ Axios Uncaught Promise
这正对应你看到的 querysbListFn → getMapData2 堆栈。
